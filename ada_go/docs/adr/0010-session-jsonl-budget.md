# ADR 0010:session-jsonl 代码预算例外

- 状态:已接受(临时例外;代码先落地,本 ADR 追认)
- 日期:2026-11-20
- 复议日期:2027-06-30
- 相关:[seam-session.md](../seam-session.md)、AGENTS §5.3/§12、[ADR 0009](0009-rpc-json-budget.md)

## 1. 背景

AGENTS §5.3 规定「单个插件 ≤ 800 行,单一职责」。`plugins/provider/session-jsonl` 实测约 953 行生产代码:

| 位置 | 行数 | 内容 |
|---|---|---|
| `provider.go` + `session.go` + `store.go` | 479 | 插件装配、会话 actor、Store 适配 |
| `file/file_store.go` | 437 | 每会话 JSONL 文件、半行恢复、fsync 语义 |
| `journal/journal.go` | 42 | 增量投影/日志辅助 |

这是一个插件(一个 session 实现),但内部按职责拆成了多个包;953 行超过 800,而拆成两个插件会让「一个会话实现」被拆散,替换实现时装配顺序与回滚变复杂。

## 2. 决策

在 **2027-06-30 前**,允许 `plugins/provider/session-jsonl` 的插件总生产代码上限为 **1000 行**,前提是:

1. 仍然一个插件、一个 seam 实现(session),不混入 LLM/tools/UI;
2. 新增功能先按现有内部包职责拆分,不得继续堆在单文件;
3. 测试不计入预算,但必须覆盖 jsonl 契约、重开、并发与半行恢复;
4. 超过 1000 行时重新评审,优先拆成独立的文件存储包,而不是继续放宽。

## 3. 替代方案(至少两个)

| 方案 | 做法 | 否决理由 |
|---|---|---|
| A. 拆成两个插件 | `session-jsonl`(actor)+ `session-jsonl-file`(存储) | seam 实现被拆散,装配/回滚复杂;存储没有独立产品价值 |
| B. 移到 platform/ | 当作 L2 基础设施,不受插件预算约束 | 会话持久化是可替换能力,不是装载机制 |
| C. 压缩到 800 行 | 删除半行恢复、fsync、并发 actor 等 | 这些是崩溃恢复与并发语义的边界,删掉会降低可靠性 |
| D. 本 ADR | 临时放宽到 1000 行,并约束内部包拆分 | 保留一个可替换实现,代价是单插件体量例外 |

## 4. 影响面

- `scripts/guard.ps1` 增加单插件预算检查后,本插件按 1000 行阈值放行;
- 不改变运行时行为;
- AGENTS §5.3 增加例外脚注。

## 5. 回滚方式

拆分实现后删除本 ADR 并把阈值改回 800;无数据迁移。

## 6. 复议条件

- `session-jsonl` 超过 1000 行;
- 或决定把文件/日志存储拆成独立 provider;
- 或 M4.5 的会话实现被替换(例如数据库 provider)。
